建置時（`scripts/build.py`）依 CMS「SEO 與追蹤碼」的欄位，把以下內容直接寫進 HTML，社群分享與搜尋引擎不需要執行 JS 就讀得到：

- Open Graph（LINE、Facebook 分享預覽）、Twitter Card
- Schema.org 結構化資料：Hotel（含 9 間 Restaurant、電話、訂位網址）、WebPage、ItemList（販售中的年菜與伴手禮及價格）、FAQPage
- `robots.txt`、`sitemap.xml`（`meta.noindex` 為 true 時禁止索引，正式上線改為 false）
- Google Search Console 驗證碼欄位

其他 SEO 原則已在網站上落實：單一 H1、區塊依序使用 H2／H3、所有圖片有替代文字、行動版優先、圖片延遲載入、`lang="zh-Hant-TW"`。

## 7. 追蹤碼（GA4 等）

在 CMS「SEO 與追蹤碼」填入代碼即可，**不開放貼任意程式碼**（避免後台帳號被盜時被植入惡意程式）：

| 欄位 | 格式 | 說明 |
|---|---|---|
| GA4 評估 ID | G-XXXXXXXXXX | 直接載入 gtag.js |
| GTM 容器 ID | GTM-XXXXXXX | 如果用 GTM 管 GA4，GA4 欄請留空，避免重複計算 |
| Google Ads 轉換 ID | AW-123456789 | |
| Meta Pixel ID | 10–20 位數字 | 使用者按「我知道了」後才載入 |

- 自動事件：`click_tel`（撥打電話）、`click_booking`（線上訂位）、`click_buy`（線上購買）、`click_outbound`（外部連結），附帶連結、按鈕文字與所在區塊。
- 採用 Google Consent Mode v2：分析預設允許，廣告相關在使用者按「我知道了」之後才允許。有設定追蹤碼時才顯示 Cookie 告知列。
- CMS 預覽與本機測試不會送出資料。
- Cookie 告知方式（告知後繼續使用即視為同意）與飯店官網相同，是否符合個資法與萬豪集團隱私規範，請法務確認。

### 登入方式
後台不另設帳號，使用 GitHub 帳號的 **fine-grained personal access token**：

1. GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token
2. Repository access 選 **Only select repositories** → `sheraton-cny-2027`
3. Permissions → Repository permissions → **Contents：Read and write**（Metadata 會自動設為唯讀）
4. 設定到期日（建議 30–90 天），產生後複製，貼到後台登入框

金鑰只保存在該瀏覽器分頁，關閉即清除；請勿傳給他人或貼到聊天、Email。

### 角色
- `cms/roles.json` 的 `publishers` 名單（目前為 TomTPE）可以發布與還原。
- 其他被加為儲存庫協作者的帳號為「編輯者」，只能儲存草稿與上傳圖片。
- 這個角色檢查在瀏覽器端執行。具有儲存庫寫入權限的人，技術上仍可直接修改檔案。若要強制，可再開啟 GitHub 分支保護。發布後的內容一律由 GitHub Actions 依相同規則重新驗證，驗證不通過就不會部署。

### 限制
- GitHub Pages 是公開網站，測試站目前設為 noindex，但知道網址的人都看得到。
- 儲存庫也是公開的，草稿 `cms/draft.json` 在 GitHub 上看得到，**未公開的價格或活動請勿先存草稿**。如需保密，請改用私人儲存庫，並搭配 GitHub Enterprise Cloud 的私人 Pages 或其他主機。
- 同時編輯時，後存檔的人會收到「草稿已被其他人更新」提示，不會互相覆蓋。
