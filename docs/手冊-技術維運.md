台北喜來登 2027 新春宣傳網站｜版本 2026-10-25

本手冊給網站維運與開發人員使用。上稿人員請看〈後台操作手冊〉，正式上線的準備事項請看〈上線準備清單〉。

## 1. 架構

```
訪客瀏覽器 ──► GitHub Pages（靜態前台 + /admin/ 後台介面）
                    ▲  GitHub Actions 驗證 → 建置 → 部署
                    │
GitHub 儲存庫 TomTPE/sheraton-cny-2027（公開）
  data/content.json   已發布內容（改動觸發部署）
  cms/draft.json      草稿（不觸發部署）
  assets/uploads/     後台上傳的圖片
                    ▲  以 GITHUB_TOKEN 寫入（金鑰只存在 Worker）
                    │
Cloudflare Worker sheraton-cny-cms（後台 API）＋ D1 資料庫（帳號、工作階段、操作紀錄）
                    ▲  帳號密碼登入、Bearer 工作階段
後台使用者瀏覽器（/admin/）
```

| 元件 | 位置 | 說明 |
|---|---|---|
| 前台 | `index.html`、`assets/js/site.js`、`assets/css/site.css` | 原生 JS，全部依 `data/content.json` 渲染 |
| 後台介面 | `admin/`（admin.js、worker-backend.js、github-backend.js、cms-config.js） | 原生 JS，不用 innerHTML，以避免 XSS |
| 後台 API | `cms-worker/src/index.js` | Cloudflare Workers；schema 在 `cms-worker/schema.sql` |
| 本機後台 | `server.py` | Python 標準函式庫；本機測試用，`validate_document` 也由 CI 使用 |
| 建置 | `scripts/build.py` | 產生 dist：移除內部欄位、寫入 SEO、加上 JS／CSS 雜湊、複製後台 |
| 部署檢查 | `scripts/check_dist.py` | 禁止檔案、內部欄位、引用檔、電話與網址、色票、SEO、robots |
| CI/CD | `.github/workflows/deploy-pages.yml` | 推送到 main 時：驗證 → 建置 → 檢查 → 部署 Pages |

## 2. 內容資料流

| 動作 | Worker 做的事 | 是否部署 |
|---|---|---|
| 儲存草稿 | 驗證後寫入 `cms/draft.json`，commit 訊息「CMS 草稿：帳號」 | 否 |
| 發布 | 驗證草稿，`revision + 1`，寫入 `data/content.json`，commit 訊息「CMS 發布 rev N：帳號」 | 是（約 30 秒建置，1–2 分鐘生效） |
| 還原 | 依 commit 識別碼取出舊版 `content.json`，寫回草稿 | 否 |
| 上傳圖片 | 依檔頭判斷格式，以 SHA-256 前 16 碼命名，寫入 `assets/uploads/` | 會觸發部署（路徑屬於 assets/**） |

併發控制：
- 草稿使用 GitHub blob sha 當作 ETag，搭配 If-Match；不一致時回 409，後台顯示「草稿已被其他人更新」。
- 兩人同時發布時，後發布者會收到 409。

## 3. 安全設計

| 項目 | 做法 |
|---|---|
| 密碼 | PBKDF2-SHA256 100,000 次（Workers 上限），每帳號隨機鹽 |
| 鎖定 | 連續 5 次錯誤鎖 15 分鐘，失敗次數以 SQL 原子遞增 |
| 工作階段 | 32 bytes 隨機權杖，D1 只存 SHA-256；有效 8 小時；透過 Authorization 標頭傳遞，不使用 Cookie |
| 來源限制 | `ALLOWED_ORIGINS`（wrangler.toml）；其他網域回 403 |
| GitHub 金鑰 | Worker secret `GITHUB_TOKEN`：fine-grained token，只授權本儲存庫，權限只有 Contents RW＋Metadata |
| 後台 CSP | 建置時寫入 meta CSP：`connect-src` 只允許 self、api.github.com 與 CMS_API 的 origin |
| 內容驗證 | 後台前端、Worker、GitHub Actions（server.validate_document）三層 |
| 稽核 | D1 audit 表記錄登入、失敗、帳號異動、草稿、發布、還原、上傳與 IP |

## 4. 日常操作指令

前置準備：使用 Node.js 24 LTS，並在 `cms-worker/` 目錄下執行。

```bash
cd cms-worker && npm ci
```

| 目的 | 指令 |
|---|---|
| 部署 Worker | `npx wrangler deploy` |
| 即時查看 API 請求 | `npx wrangler tail sheraton-cny-cms` |
| 更換 GitHub 金鑰（從剪貼簿讀取，不顯示） | `sh scripts/set_github_token.sh` |
| 建立緊急管理員 | `python3 scripts/create_admin.py <帳號> <顯示名稱>`，再依畫面提示執行 `wrangler d1 execute … --remote --file` |
| 查詢帳號 | `npx wrangler d1 execute sheraton-cny-cms --remote --command "SELECT username, role, disabled FROM users"` |
| 查詢操作紀錄 | `npx wrangler d1 execute sheraton-cny-cms --remote --command "SELECT ts, username, action, detail FROM audit ORDER BY id DESC LIMIT 50"` |
| 本機建置與檢查 | `python3 scripts/build.py --env test --out /tmp/dist --with-admin --repo TomTPE/sheraton-cny-2027` → `python3 scripts/check_dist.py /tmp/dist --allow-admin` |
| 本機整合測試 | 見 `cms-worker/test/worker_test.py` 檔頭說明（`wrangler dev --local` 加本機測試帳號，共 35 項） |

GitHub 儲存庫變數 `CMS_API` 決定後台使用哪種登入方式。設定時只能填網址的 origin，不可加路徑。

## 6. 部署失敗排查

1. 打開 GitHub → Actions，點最新一次「Deploy test site to GitHub Pages」。
2. 依失敗的步驟處理：

| 失敗步驟 | 原因 | 處理 |
|---|---|---|
| 驗證 content.json | 內容不符合規則，錯誤會以 `::error::路徑：訊息` 列出 | 在後台修正後重新發布；必要時從「版本紀錄」還原 |
| 建置 | `CMS_API` 格式錯誤、圖片引用不存在 | 修正變數或圖片路徑 |
| 檢查建置產物 | 色票外的顏色、內部欄位外洩、robots 或 SEO 標記遺失 | 依錯誤訊息修正程式 |
| deploy | GitHub Pages 服務異常 | 到 Actions 重新執行（Re-run） |

驗證失敗時，網站會維持在上一次成功的版本，不會出現空白頁。

## 7. 後台 API 排查

| 現象 | 可能原因 | 處理 |
|---|---|---|
| 「Worker 尚未設定 GitHub 金鑰」 | `GITHUB_TOKEN` 是空值 | 執行 `sh scripts/set_github_token.sh` |
| 「金鑰無效或已過期（GitHub 401）」 | 金鑰過期或已被撤銷 | 到 GitHub 重新產生金鑰，再執行上一列的腳本 |
| 「金鑰權限不足（Resource not accessible…）」 | 金鑰缺少 Contents 權限，或沒有勾選本儲存庫 | 到 GitHub 編輯金鑰權限，按 Update 後立即生效 |
| 「無法連線到後台服務」 | Worker 停擺或超過每日額度（Error 1027） | 檢查 `/api/health` 與 Cloudflare 儀表板 |
| 全部帳號都無法登入 | 沒有管理員或帳號被鎖定 | 用 `create_admin.py` 建立緊急管理員 |

**金鑰到期提醒**：fine-grained token 有到期日，請在行事曆設定到期前 2 週的提醒，以免年節檔期中後台突然無法存檔。

## 8. 快取

- GitHub Pages 預設回應 `cache-control: max-age=600`，也就是快取 10 分鐘。
- `index.html` 引用的 JS 與 CSS 在建置時會加上內容雜湊（`?v=…`），避免新版 HTML 搭配到快取的舊版 JS。
- `content.json` 以 `cache: 'no-cache'` 讀取，每次都向伺服器確認是否有新版。

## 9. 備份與還原

| 資料 | 備份方式 |
|---|---|
| 網站內容、圖片 | Git 歷史即是完整備份；可從後台「版本紀錄」或 git 還原 |
| 帳號與操作紀錄（D1） | Cloudflare D1 Time Travel，免費方案可回溯 7 天；重要時點可用 `wrangler d1 export sheraton-cny-cms --remote --output backup.sql` 匯出 |
| Worker 程式與設定 | 都在儲存庫 `cms-worker/`；機密（GITHUB_TOKEN）不在儲存庫，遺失時重新設定即可 |

D1 匯出檔含有密碼雜湊，請存放在加密的位置，不要提交到儲存庫。

## 10. 已知限制與待辦

- 儲存庫是公開的，`cms/draft.json` 在 GitHub 上看得到。未公開的價格或活動請勿先存草稿，或改用私人儲存庫，見〈上線準備清單〉。
- GitHub Pages 無法自訂回應標頭（CSP、X-Frame-Options 等），前台只能使用 meta 標籤，見〈上線準備清單〉第 4 節。
- 舊的 GitHub 金鑰登入程式（`admin/github-backend.js`）目前沒有使用，可以移除。
- Cookie 告知列只有「我知道了」，沒有拒絕選項，需要法務確認。
