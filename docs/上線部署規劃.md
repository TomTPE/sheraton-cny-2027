# 2027 新春網站｜上線部署規劃

2026-10-23 草擬。本文件僅為規劃，尚未建立任何 GitHub 儲存庫、未部署、未對外公開。所列服務方案與價格、功能以撰寫時所知為準，採用前須至各官方文件重新確認。

## 1. 先釐清：要部署的是什麼

| 部分 | 性質 | 可放在哪裡 |
|---|---|---|
| 前台（index.html、assets、data/content.json） | 純靜態檔 | 任何靜態主機：GitHub Pages、Cloudflare Pages、Netlify、飯店現有主機 |
| 後台 CMS（admin/、server.py） | 需要執行 Python 的伺服器，含權限與寫檔 | **不能**放 GitHub Pages；本機使用，或部署到可執行程式的主機（雲端 VM／容器） |

建議分兩階段：
1. **測試環境**：只部署前台。內容由本機 CMS 編輯、發布後，把 `data/content.json` 推到 GitHub，自動更新測試站。
2. **正式環境**：前台部署到飯店網域；CMS 視維運能力決定，可以維持「本機編輯＋Git 發布」，或改用正式的 Headless CMS（見 docs/CMS規劃.md）。

## 2. 上線前必須處理的風險

### 2.1 不可推到 GitHub 的檔案
目前專案根目錄（`台北喜來登 2027 新春宣傳/`）含有不應公開的資料，**不要把整個資料夾推上 GitHub**：

- `除夕餐價/`、`proposal/data-audit/`：飯店內部 MEMO，含主管簽核、員工分機與姓名、食材成本（礁溪寒沐 MEMO）等。
- `CIS/Brand Book/`、`proposal/she-*.txt`：Marriott 品牌指南，頁尾標示為 Company Proprietary Information。
- `handover/`、`backups/`、`.textClipping`：交接紀錄與歷史原稿。
- CMS 執行期檔案：`.cms-tokens.json`（登入權杖）、`data/draft.json`、`data/revisions/`、`data/audit.log`。

做法：**以 `site-2027/` 單獨建立一個新的儲存庫**，並使用已準備好的 `site-2027/.gitignore`。

### 2.2 測試站也是公開的
- GitHub Pages 的網站預設任何人都能開啟，即使儲存庫是私有的。只有 GitHub Enterprise Cloud 提供有存取控制的私有 Pages（以 GitHub 官方文件為準）。
- 私有儲存庫要使用 Pages，需付費方案（GitHub Pro／Team／Enterprise）；免費方案只能用公開儲存庫，原始碼也會公開。
- `noindex` 只能請搜尋引擎不要收錄，**不能阻止有連結的人瀏覽**。

測試站目前含有尚未核定的價格、示意活動與授權未確認的圖片。如果測試站不能讓外部看到，建議改用有存取控制的方案（見第 3 節選項 B）。

### 2.3 內部校稿欄位
`content.json` 內的 `verify`（待確認事項）與 `source`（資料來源）是內部用欄位。`scripts/build.py` 建置時會自動移除，部署的一律是 `dist/`，不要直接部署原始資料夾。

## 3. 測試環境方案

| 方案 | 存取控制 | 成本（撰寫時所知，需再確認） | 適合情境 |
|---|---|---|---|
| A. GitHub Pages | 無（公開網址），Enterprise Cloud 才有私有 Pages | 公開儲存庫免費；私有儲存庫需付費方案 | 內容可接受被外部看到、只想快速給內部看 |
| B. Cloudflare Pages ＋ Cloudflare Access | 可限定公司 Email 或指定帳號登入 | Pages 有免費額度；Access 有小團隊免費額度 | **建議**：內容未核定、需限內部人員瀏覽 |
| C. Netlify／Vercel 密碼或登入保護 | 有，但多屬付費功能 | 依方案 | 團隊已在使用這些服務時 |

不論哪個方案，原始碼都放在 GitHub（私有儲存庫），差別只在部署到哪裡。

### 方案 A：GitHub Pages 操作步驟（已備好設定檔）

已在 `site-2027/` 準備好：
- `.github/workflows/deploy-pages.yml`：推送到 `main` 時自動建置並部署；使用 actions/checkout@v4、configure-pages@v5、upload-pages-artifact@v3、deploy-pages@v4，啟用前請確認仍為維護中版本。
- `scripts/build.py`：產生 `dist/`，強制 `noindex`、移除校稿欄位、排除後台與文件。
- `.gitignore`：排除權杖、草稿、版本快照、上傳區與建置產物。

步驟：
1. 確認公司是否允許使用 GitHub、使用個人或組織帳號，以及儲存庫的公開／私有層級。
2. 在 GitHub 建立新儲存庫（建議放在公司組織下、設為私有），例如 `sheraton-cny-2027`。
3. 在本機把 `site-2027/` 初始化為 Git 儲存庫並推送：
   ```bash
   cd site-2027
   git init -b main
   git add .
   git commit -m "2027 新春網站 v2.0 測試版"
   git remote add origin <儲存庫網址>
   git push -u origin main
   ```
   推送前先執行 `git status` 確認沒有 `.cms-tokens.json`、`data/draft.json` 等檔案。
4. 在儲存庫 Settings → Pages → Source 選擇「GitHub Actions」。
5. 等 Actions 執行完成，網址為 `https://<帳號或組織>.github.io/sheraton-cny-2027/`。
6. 之後更新內容：本機啟動 CMS 編輯並發布 → `git add data/content.json && git commit && git push` → 自動重新部署。

### 方案 B：Cloudflare Pages ＋ Access 重點
- 連接同一個 GitHub 儲存庫；建置指令 `python3 scripts/build.py --env test --out dist`，輸出目錄 `dist`。
- 在 Cloudflare Zero Trust 為測試網址建立 Access 應用程式，只允許指定 Email 網域（例如公司網域）登入。

## 4. 正式上線方案

### 4.1 網域
- 官網 `www.sheratongrandtaipei.com` 由寒舍餐旅管理顧問股份有限公司管理（官網頁尾標示）。正式站需由飯店 IT 決定放在：
  - 子網域，例如 `cny2027.sheratongrandtaipei.com`（DNS 指向靜態主機，最容易），或
  - 子路徑，例如 `www.sheratongrandtaipei.com/cny2027/`（需放進現有主機或設定反向代理）。
- 需要 HTTPS 憑證（靜態主機多數會自動簽發）。

### 4.2 正式建置
```bash
python3 scripts/build.py --env prod
```
`meta.noindex` 必須先在 CMS 改為 `false`，否則建置會中止，避免正式站被誤設為不收錄。

### 4.3 CMS 正式化（擇一）
| 做法 | 說明 | 注意 |
|---|---|---|
| 維持本機 CMS＋Git 發布 | 編輯在本機用 server.py，發布後 push content.json | 最簡單；需有人會操作 Git，可再包成一鍵腳本 |
| CMS 部署到雲端主機 | server.py 放在雲端 VM／容器 | 必須加上 HTTPS、SSO 或個人帳號、備份；目前共用權杖的設計不足以直接上網 |
| 改用 Headless CMS | 例如 Decap、Strapi、Payload | 需再開發串接；授權與版本須於選型時查證 |

### 4.4 正式上線須補齊
- **SEO／分享**：canonical、Open Graph 圖文（需正式主視覺）、favicon、sitemap。
- **分析**：GA4／GTM 需飯店核准帳號。依個資法與官網現行做法加 Cookie 告知；事件包含電話點擊、線上訂位、線上購買外連。外連點擊不等於成交。
- **安全標頭**：CSP（允許 Google Fonts）、HSTS、X-Content-Type-Options。
- **效能**：圖片轉 WebP／AVIF 並提供多尺寸（目前為 1400px JPEG，約 2.7 MB 總量）；手機 4G 目標 LCP ≤ 2.5 秒、CLS ≤ 0.1，需以實機量測。
- **字體**：決定是否接受 Google Fonts 對外連線；若不接受，改為自行託管字型子集。
- **無障礙**：鍵盤操作、螢幕閱讀器、色彩對比的完整檢核。
- **錯誤處理**：404 頁；content.json 載入失敗時的備援訊息（已有）。

## 6. 回復方案
- **前台**：每次部署都對應一個 Git commit；有問題時還原 `data/content.json` 或整個 commit 並重新推送，即可回到前一版。GitHub Pages 與 Cloudflare Pages 也都保留部署紀錄。
- **內容**：CMS 的 `data/revisions/` 保留每次發布的快照，可在後台還原到草稿後重新發布。
- 上線前實際演練一次回復流程並記錄時間。
