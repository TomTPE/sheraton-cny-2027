## 1. 主機與存儲空間

### 1.1 目前的用量（事實，2026-10-25 實測）
| 項目 | 數值 |
|---|---|
| 網站建置產物 | 約 7.5 MB、43 個檔案，含後台 |
| 照片 | 官網照片 13 張（約 4.9 MB），每張 1600 px、品質 70 |
| 內容資料 content.json | 約 70 KB |
| 後台資料庫 D1 | 帳號、工作階段、操作紀錄，預估小於 1 MB |

### 1.2 主機方案比較
| 方案 | 優點 | 限制（事實） | 建議 |
|---|---|---|---|
| **GitHub Pages**（目前的測試站） | 免費，已串好 CI/CD | 發布大小 ≤ 1 GB；頻寬軟上限每月 100 GB；部署逾時 10 分鐘；**不允許作為線上事業或電子商務的免費主機**；無法自訂回應標頭（CSP、X-Frame-Options） | 只用於測試站 |
| **Cloudflare Pages** | 免費方案就能用 `_headers` 設定安全標頭；可與 Worker 放在同一帳號；支援自訂網域與自動 HTTPS | 免費方案：每月 500 次建置、每站 20,000 個檔案、單檔 ≤ 25 MiB；`_headers` 最多 100 條規則 | **建議作為正式站**（流程改動最少） |
| 飯店既有主機（官網 Apache） | 與官網同網域，由 IT 統一管理 | 需要 IT 排程部署，CMS 發布後要另外同步 | 若 IT 政策要求內部託管時採用 |

### 1.3 頻寬估算（建議）
- 首次造訪約下載 2–3 MB（圖片延遲載入，實際依捲動深度而定）。
- 假設年節檔期 3 萬次造訪 × 2.5 MB ≈ 75 GB，已接近 GitHub Pages 每月 100 GB 的軟上限，這也是建議換主機的原因之一。
- 可再降低用量的做法：圖片改用 WebP 或 AVIF、提供多種尺寸（srcset）。

### 1.4 後台 API（Cloudflare Workers＋D1）用量（事實）
| 項目 | 免費方案上限 | 本專案預估 |
|---|---|---|
| Workers 請求 | 每天 100,000 次（UTC 午夜重設）；超過時回傳 Error 1027 | 每天數百次 |
| 單一請求 CPU 時間 | 10 ms（等待網路的時間不計） | 登入用的 PBKDF2 運算接近上限，需要觀察 |
| D1 單一資料庫 | 500 MB；帳號總計 5 GB | 小於 1 MB |
| D1 讀取／寫入 | 每天 500 萬列／10 萬列 | 遠低於上限 |
| D1 Time Travel | 可回溯 7 天 | — |

**建議**：上線後到 Cloudflare 儀表板確認登入請求的 CPU 時間。如果常超過 10 ms，可以改用 Workers 付費方案。

## 2. HTTPS

| 項目 | 說明 |
|---|---|
| 憑證 | **事實**：GitHub Pages 自訂網域使用 Let's Encrypt 自動簽發；Cloudflare Pages 自訂網域也是自動簽發。官網目前同樣使用 Let's Encrypt，憑證到期日為 2026-12-04，應已設定自動續約，**請 IT 確認** |
| 強制 HTTPS | GitHub Pages 要勾選「Enforce HTTPS」；Cloudflare 要開啟「Always Use HTTPS」 |
| HSTS | **事實**：主網域 `sheratongrandtaipei.com` 與 `www` 都回應 `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`；查詢 hstspreload.org，目前**不在**瀏覽器的 preload 名單中 |
| HSTS 的影響 | 曾造訪過主網域的瀏覽器，在一年內對**所有子網域都只會用 HTTPS 連線**。新子網域如果 HTTPS 還沒生效，這些訪客會打不開。所以要先確認憑證已經生效，再對外公布網址 |
| 混合內容 | 全站資源都已使用 https。Google Fonts、TableCheck、LIKEGO、GA 都是 https |
| TLS 版本 | **建議**只開放 TLS 1.2 以上（Cloudflare：SSL/TLS → Edge Certificates → Minimum TLS Version 設為 1.2） |
| 驗證工具 | SSL Labs（https://www.ssllabs.com/ssltest/ ），目標評等 A 以上 |

## 3. 網域安全

| # | 項目 | 狀態與建議 |
|---|---|---|
| 1 | **網域註冊商帳號** | **事實**：sheratongrandtaipei.com 的 DNS 由 GoDaddy（domaincontrol.com）代管。**建議**開啟兩步驟驗證、Domain Lock（Transfer Lock）、自動續約，並確認聯絡信箱是公司共用信箱，不是個人信箱 |
| 2 | **DNSSEC** | **事實**：目前查不到 DS 紀錄，也就是沒有啟用 DNSSEC。**建議**評估啟用，可以防止 DNS 被竄改 |
| 3 | **CAA 紀錄** | **事實**：目前沒有 CAA 紀錄。**建議**新增，限制只有實際使用的憑證機構（例如 `letsencrypt.org`，以及 Cloudflare 使用的 CA）能簽發憑證；新增前請先確認官網與其他子網域使用哪些 CA，以免影響續約 |
| 4 | **子網域接管風險** | 使用 GitHub Pages 自訂網域時，**必須在 GitHub 驗證網域**（新增 TXT 紀錄 `_github-pages-challenge-<帳號>.<網域>`），並且不要使用萬用字元 DNS（`*.`）。網站下架時，**要先刪除 DNS 紀錄**，再刪除 Pages 或儲存庫 |
| 5 | DNS 紀錄 | 子網域使用 CNAME 指向主機（例如 `<project>.pages.dev` 或 `<user>.github.io`），**不要**加上多餘的 A 或 AAAA 紀錄，否則可能導致憑證無法簽發 |
| 6 | 權限最小化 | GitHub：改用組織帳號、開啟兩步驟驗證、main 分支保護；Cloudflare：開啟兩步驟驗證、帳號成員只給必要角色；fine-grained token 設定到期日 |
| 7 | 監控 | **建議**設定網站可用性監控（例如 UptimeRobot），以及憑證到期提醒 |

## 4. 網站安全標頭

GitHub Pages 無法設定以下標頭，改用 Cloudflare Pages 後可以在 `_headers` 檔設定。**建議**的內容如下，上線前須實測，確認 GA、TableCheck 等外部連結都正常：

```
/*
  Strict-Transport-Security: max-age=31536000; includeSubDomains
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=(), geolocation=()
  X-Frame-Options: SAMEORIGIN
  Content-Security-Policy: default-src 'self'; script-src 'self' https://www.googletagmanager.com https://connect.facebook.net; style-src 'self' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' https: data:; connect-src 'self' https://*.google-analytics.com https://www.googletagmanager.com https://raw.githubusercontent.com https://api.github.com <CMS_API>; frame-ancestors 'self'
/admin/*
  Cache-Control: no-store
  X-Robots-Tag: noindex, nofollow
```

**注意**：目前前台有少量 inline style（`style="--d:…"`）。CSP 若沒有加上 `style-src 'unsafe-inline'`，需要先改寫程式。這一點要先在測試環境驗證。

驗證工具：MDN HTTP Observatory（https://developer.mozilla.org/en-US/observatory ）。

## 5. 個資與隱私（資訊提供，請法務確認）

- 本網站本身**不蒐集表單資料**。訂位與購物都導向 TableCheck、LIKEGO 等外部平台，由各平台負責告知。
- 若啟用 GA4 或 Meta Pixel，會透過 Cookie 蒐集瀏覽行為。依《個人資料保護法》第 8 條，蒐集時應告知蒐集目的、資料類別、利用方式等。網站已提供告知列與隱私權政策連結（連到官網）。**請法務確認**：
  - 「我知道了」這種默示同意是否足夠，還是需要「拒絕」選項；
  - 萬豪集團隱私規範是否有額外要求。
- 依該法第 20-1 條，非公務機關應採取適當的安全措施。後台已具備密碼雜湊、鎖定、操作紀錄、最小權限，可作為佐證資料。
- 操作紀錄 D1 audit 會儲存登入 IP，**建議**訂定保留期限，例如檔期結束後 6 個月刪除。

## 6. SEO 與數據上線切換

上線當天，在後台「網站設定」與「SEO 與追蹤碼」完成以下設定：
1. 「網站設定 → 禁止搜尋引擎索引」改成 **否**。正式環境建置時，若此項仍為「是」，建置會中止。
2. 「SEO → 正式網址」改成正式網域，必須以 `/` 結尾。
3. 填入 GA4／GTM ID、Google Search Console 驗證碼。
4. 發布後：
   - 在 Search Console 提交 `sitemap.xml`；
   - 用 Rich Results Test（https://search.google.com/test/rich-results ）檢查結構化資料；
   - 用 LINE 或 Facebook 的分享偵錯工具確認預覽圖。
5. GA4 即時報表確認 `page_view`、`click_tel`、`click_booking` 都有進來。
6. 正式站與測試站並存期間，測試站要維持 noindex，或直接下架，以免搜尋結果出現重複內容。

## 8. 上線當天流程

1. （T－1 天）凍結內容，發布最終版本，記下目前的 rev。
2. 部署到正式主機，並設定自訂網域與 HTTPS，先用**主機預設網址**驗收。
3. 調整 DNS：新增 CNAME，等憑證生效。若主網域有 HSTS includeSubDomains，一定要等 HTTPS 生效後才對外公布網址。
4. 在後台把 Worker 的 `ALLOWED_ORIGINS` 和儲存庫變數 `CMS_API` 改成正式網域，重新部署 Worker 與網站。
5. 依第 6 節完成 SEO 與追蹤碼設定，然後發布。
6. 執行第 7 節的冒煙測試：首頁、電話、訂位、購物、後台登入與存草稿。
7. 對外公布網址：官網年節專區、LINE、社群。

**回滾方式**：
- 內容有問題：在後台「版本紀錄」還原到上一版後再發布。
- 網站有問題：在 GitHub Actions 重新部署上一個成功的 commit。
- 網域有問題：把 DNS 改回原本的設定。

## 9. 檔期結束後

- 網站改為「活動已結束」頁面，或轉址到官網年節專區（例如 2027/3/1 起）。
- 停用後台帳號，撤銷 GitHub 金鑰，視需要刪除 Worker 與 D1，先匯出操作紀錄留存。
- 如果不再使用子網域，**先刪除 DNS 紀錄，再關閉主機**，以避免子網域被接管。
